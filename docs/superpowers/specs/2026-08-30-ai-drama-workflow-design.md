# AI 漫剧/短剧工作台真实流程设计

## 1. 文档目的

本设计解决当前工作台“能打开、能输入，但不知道解析了什么，也无法从原稿走到评分、改写、分镜”的问题。

本版本明确：

- 一句话创意与已有剧本采用两条不同入口。
- 每个阶段必须产生可查看、可编辑、可追溯的结构化产物。
- 原稿只读，任何 AI 或人工修改都产生新版本。
- 一个项目保存完整创作链路；模型 API 配置属于软件级配置，不属于项目正文。
- 大模型负责语义理解和创作建议，确定性规则负责校验、版本、命名、时长和安全。

本文件是后续 sub-driven 开发的共同依据。在用户审阅并确认前，不进入实现阶段。

## 2. 产品目标

用户可以从一句话创意或一份已有原稿开始，完成以下闭环：

```text
输入
  -> 创意诊断或原稿解析
  -> 故事方案/故事圣经
  -> 剧本评分
  -> 用户指定目标的受控改写
  -> 版本对比与确认
  -> 资产提取
  -> 分镜组与生成提示词
  -> 连续性/时长/命名检查
  -> Markdown/JSON 导出
```

产品不宣称评分绝对客观。评分必须展示目标、权重、证据、原因和建议，允许用户复核和修改。

## 3. 两类输入入口

### 3.1 一句话创意入口

适用于一句话、几句话、标题或极短故事概念。

```text
一句话创意
  -> 创意诊断
  -> 故事方案
  -> 人物与故事圣经
  -> 短剧剧本初稿
  -> 剧本评分
  -> 受控改写/定稿
  -> 资产/分镜/提示词
```

创意诊断至少输出：

- 题材和类型候选
- 主角、目标、阻力、对手
- 核心冲突和情绪卖点
- 可视化场景机会
- 短剧化风险
- 缺失信息和待确认问题
- 适合的集数、单集时长和受众建议

故事方案至少输出：

- 一句话梗概
- 三幕或分段结构
- 主要人物和人物关系
- 主线冲突、阶段目标、关键反转
- 分集目录和每集结尾钩子
- 需要用户确认的创作假设

### 3.2 已有原稿入口

适用于小说章节、故事梗概、已有短剧剧本、Markdown 或 TXT 文件。

```text
原稿
  -> 原稿保存
  -> 结构化解析
  -> 解析结果复核
  -> 故事圣经
  -> 剧本评分
  -> 受控改写/定稿
  -> 资产/分镜/提示词
```

结构化解析至少识别：

- 集、场、时间、地点和内外景
- 出场人物和人物关系
- 动作、对白、旁白、VO、OS
- 事件、冲突、反转和悬念
- 可直接拍摄的内容与抽象叙述
- 不确定的角色、时间、地点和因果关系
- 原文位置和引用片段

解析结果必须显示在界面中，不能只显示“分析完成”。

## 4. 端到端用户流程

### 阶段 0：项目

用户新建项目并填写：

- 项目名称
- 输入类型：一句话创意/小说/章节/梗概/已有剧本
- 题材（可选）
- 目标受众（可选）
- 目标集数和单集时长（可选）

点击“创建项目”后，必须生成项目记录并打开项目详情页。最近项目列表中的每个项目必须可以打开、重命名和软删除。

### 阶段 1A：一句话创意

用户输入创意，点击“保存创意”，再点击“开始创意诊断”。

界面展示：

- 原始创意文本
- 创意诊断报告
- 故事方案草稿
- 待确认问题
- 使用的模型、配置和 Prompt 版本

用户确认故事方案后，才能生成故事圣经和短剧剧本初稿。

### 阶段 1B：已有原稿

用户粘贴文本或导入 TXT/Markdown 文件，点击“保存原稿”，再点击“开始解析”。

界面展示：

- 原稿正文
- 原稿类型和统计信息
- 结构化节点树
- 人物、对白、动作和场景摘要
- 待复核列表
- 每条待复核内容的原文位置

用户可以修正解析结果。修正后的结果作为“解析确认快照”保存，不覆盖原稿。

### 阶段 2：故事圣经

系统从创意诊断或解析确认快照提取故事圣经。

故事圣经包含：

- 人物卡和人物关系
- 世界观规则
- 时间线
- 场景清单
- 道具和 UI 清单
- 锁定事实
- 待确认事实

用户可以编辑和锁定条目。锁定条目后，后续改写和生成不得静默改变；如确需改变，必须产生影响范围和版本差异。

### 阶段 3：剧本诊断

对已确认的故事方案或剧本版本执行评分。

固定八个维度：

1. 钩子
2. 冲突
3. 人物动机
4. 节奏
5. 反转
6. 对白
7. 画面化
8. 连续性

每个维度必须有分数、权重、原因、原文引用、位置和改进建议。评分记录必须关联输入版本，不允许只保存最后一个总分。

### 阶段 4：受控改写

用户选择改写范围：全文、单集、场次、段落或指定问题。

用户可以输入自定义提示词。提示词按以下优先级合并：

```text
内部安全与格式规则
  > 故事圣经锁定事实
  > 项目目标与任务指令
  > 用户自定义提示词
  > 输出格式要求
```

模型必须返回结构化改写结果，包括修改正文、修改摘要、删除/新增/重写项、事实变化和风险提示。

每次改写产生独立剧本版本。用户可以查看差异、命名版本、恢复旧版本或确认定稿。

### 阶段 5：资产提取

只有确认或锁定的剧本版本才能进入资产提取。

系统提取并展示：

- 人物资产
- 场景资产
- 道具资产
- UI 资产
- 重复出现的实体
- 未命名但重复出现的实体
- 资产首次出现位置和全部引用位置

资产使用稳定的 `@人物`、`@场景`、`@道具`、`@UI` 命名。资产可以编辑、合并、删除和锁定。

### 阶段 6：资产板提示词

每个资产生成独立、可复制的提示词块。

提示词至少包含：

- 用途
- 风格基线
- 拆分细节
- 构图/版式要求
- 适用的色彩约束
- 完整生成提示词
- 避免项

使用本地参考 PNG 时保存绝对路径、尺寸和 hash；未经用户授权，不把参考图内容上传给外部模型。

### 阶段 7：分镜与镜头组

基于确认剧本和资产清单生成分镜。

每个镜头至少包含：

- 集号、场号、镜头号
- 景别和机位
- 镜头运动
- 画面动作
- 对白/旁白
- 音效
- 时长
- 资产引用
- 与前后镜头的承接关系

Seedance2 镜头组约 10 秒，包含 3-4 个 timed shots、四宫格剧情图提示词和视频提示词。系统必须校验镜头 ID、资产 ID、对白锁定、总时长和默认负面约束。

### 阶段 8：导出

支持：

- Markdown 生产稿
- JSON 交换文件
- 单独复制任一提示词块
- 导出前安全扫描

导出结果必须保留项目、版本、集、场、镜头和资产关系；API Key 不得出现在正文、导出物或日志中。

## 5. 项目数据模型

项目是完整创作链路的根，不是只有一个名字和一段文本。

```text
Project
├── project metadata
├── source documents                 原始输入，只读
├── intake/parse snapshots           解析或创意诊断快照
├── story bible                      项目级设定与锁定事实
├── screenplay versions              原稿衍生和人工/AI版本
├── score reports                    绑定具体版本的诊断报告
├── rewrite records                  每次改写的提示词、范围和差异
├── assets                           人物/场景/道具/UI
├── board prompts                    资产板提示词
├── shot groups                      分镜和视频提示词
├── generation records               模型、参数、Prompt、输入版本
├── task runs                        任务状态、进度、错误和重试
└── export records                   导出格式、路径和 hash
```

### 5.1 原稿规则

原稿保存以下信息：

- 稳定 ID
- 所属项目 ID
- 输入类型
- 文件名或输入来源
- 原始正文
- 字符数、hash、编码
- 创建时间和更新时间

原稿正文永远只读。任何编辑必须产生新版本或解析修正快照。

### 5.2 版本规则

版本链示例：

```text
原稿版本
  -> AI 改写版本 1
  -> 人工修订版本
  -> AI 改写版本 2
  -> 确认定稿版本
```

每个版本保存：

- 版本 ID、父版本 ID、源输入版本 ID
- 版本号和用户名称
- 完整结构化剧本
- 渲染后的 Markdown
- 状态：草稿、待确认、已确认、归档
- 创建时间和更新时间

### 5.3 模型配置规则

模型配置是软件级资源：

```text
软件模型配置
├── Ollama 本地
├── OpenAI-compatible
├── DeepSeek-compatible
└── 其他自定义 API
```

项目只记录“本次生成使用的配置 ID、提供方、模型名和参数”，不复制 API Key。配置支持新增、编辑、删除、连接测试和切换。密钥使用本地安全存储或本地加密存储，不进入项目文件、导出物和日志。

## 6. 大模型与确定性代码的边界

### 6.1 大模型负责

- 语义理解
- 创意诊断
- 结构化抽取
- 故事方案生成
- 人物和故事圣经建议
- 评分理由和证据候选
- 受控改写
- 分镜动作与镜头设计
- 资产描述和生成提示词
- 连续性问题的语义发现

### 6.2 确定性代码负责

- 输入文件大小、扩展名和编码检查
- JSON Schema 校验
- 原稿只读和版本链
- 故事圣经锁定规则
- 资产命名和引用完整性
- 镜头时长和 ID 校验
- 导出格式和安全脱敏
- 任务取消、超时、重试和状态机
- 数据库事务和恢复

模型返回无效 JSON、缺字段、违反锁定事实或违反时长约束时，系统必须保留当前内容，显示可理解错误，并提供重试、编辑或切换模型操作。

## 7. 页面与状态要求

每个阶段页面都必须有：

- 当前项目和当前版本
- 输入来源和上游版本
- 明确的开始操作按钮
- 进行中状态和进度
- 成功后的结构化结果
- 失败原因和恢复操作
- 返回上一步和查看历史版本

禁止只显示无法操作的状态文案，例如“等待解析”或“工作区已就绪”。状态文案必须伴随下一步按钮或结果区域。

关键状态：

```text
idle -> ready -> running -> succeeded
                         \-> failed -> retrying
                         \-> cancelled
```

## 8. Sub-driven 开发拆分建议

确认本设计后，再按以下相互隔离的子任务推进：

### 子任务 A：项目与持久化闭环

- 项目创建、打开、重命名、软删除、恢复
- 原稿保存和只读展示
- 解析快照、版本和项目图落库
- 关闭重启后的数据恢复

### 子任务 B：双入口输入与解析

- 一句话创意诊断
- 已有原稿结构化解析
- 解析结果树、待复核和人工修正
- JSON Schema 和失败恢复

### 子任务 C：故事圣经与版本中心

- 故事圣经生成、编辑、锁定
- 剧本版本列表、差异、命名、恢复和确认
- 锁定事实影响检查

### 子任务 D：评分与受控改写

- 八维评分报告
- 引用定位和建议
- 用户范围选择和自定义提示词
- 改写差异、版本生成和任务状态

### 子任务 E：资产、分镜与导出

- 资产提取和命名引用
- 资产板提示词
- Seedance2 镜头组、四宫格和视频提示词
- 连续性、时长、导出和回读

### 子任务 F：模型配置与安全

- Ollama/API 配置中心
- 模型列表、连接测试和切换
- OS 密钥链或本地加密存储
- 错误分类、日志脱敏和安全扫描

每个子任务必须同时交付界面、领域逻辑、持久化、错误状态和自动化测试，不接受只有模型 Demo 的半功能切片。

## 9. 验收标准

### P0 主流程

- 新建项目后刷新/重启，项目仍存在。
- 一句话创意可以看到创意诊断和故事方案，不只是状态文字。
- 已有原稿可以看到结构化节点、对白、动作和待复核项。
- 原稿不会被 AI 改写覆盖。
- 每次 AI 改写产生可恢复的新版本。
- 评分报告八维齐全，每项可定位到证据。
- 只有确认剧本才能进入资产和分镜阶段。
- 分镜包含完整镜头字段并通过 ID、命名、对白和时长检查。
- 任一阶段失败不会覆盖已有内容，支持重试或切换模型。
- Markdown/JSON 导出可以被系统回读，关系不丢失。

### P0 安全

- API Key 不进入项目数据、导出、日志和错误提示。
- Ollama 模式下编辑、版本恢复和导出不依赖网络。
- 外部模型返回内容不会被当作代码或文件路径执行。

### P1 质量

- 相同输入、模型和 Prompt 版本可以复现相同结构。
- 评分、改写、分镜和提示词均显示模型、参数、输入版本和 Prompt 版本。
- 10,000 字中文原稿可以完成导入、解析、评分和导出。

## 10. 暂不纳入本轮

- 用户登录和云端同步
- 多人协作和权限系统
- 平台代购模型额度
- 内置图像/视频生成服务
- 自动发布到第三方平台
- 不可追溯的一键“全自动成片”

## 11. 设计结论

本产品不是一个聊天框，也不是一个只生成 Markdown 的 Demo。核心产品价值是：

```text
结构化输入
  + 可解释诊断
  + 可控改写
  + 可恢复版本
  + 锁定故事事实
  + 可执行分镜和提示词
  + 完整项目资产链路
```

后续实现必须以本设计为边界，优先打通“创建项目 -> 保存原稿/创意 -> 真实解析/诊断 -> 可见结果 -> 版本保存”的第一条纵向链路。
